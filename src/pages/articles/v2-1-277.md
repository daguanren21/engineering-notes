## 一次发布里最密集的是修复，不是功能

这个版本的改动列表里，新增能力只有寥寥几条，其余几乎全是修复。这不是一次平淡的迭代，而是一次把长期积累的边界情况集中清算的发布。对使用 Claude Code 做自动化的人来说，值得读的不是新增了什么，而是它承认了哪些此前会静默出错的地方。

修复可以归成三类：进程与状态的生命周期、工具调用的语义正确性、以及 prompt cache 的完整性。三类问题有一个共同点——它们都不在正常路径上，只在特定组合下触发，而且触发时往往没有清晰报错。

```flow
title: 三类修复各自守住的边界
caption: 从上到下依次是进程层、工具层、缓存层，每一层都在把静默失败变成显式信号
layer: 进程与状态 | 退出码与报错 | 会话恢复 | 后台任务
layer: 工具语义 | Write 与 Edit | Grep 与 Glob | 权限判定
layer: 缓存完整性 | 首条消息 | 附件重渲染 | MCP 工具定义
```

## 静默失败被逐个改成显式报错

最典型的是 `claude -p` 和 Agent SDK 会话：内部错误之后可能挂起且没有任何结果。现在它们会报告错误并以退出码 1 结束。对把 Claude Code 嵌进 CI 或流水线的人来说，这一条比任何新功能都重要——挂起意味着超时和不可归因的失败，退出码意味着可以分支处理。

同类改动还有几处。Grep 和 Glob 在系统进程、内存或文件句柄耗尽导致搜索无法启动时，此前报告“无匹配”，现在返回明确的错误。Write 工具在目标路径是已存在目录时，此前被当作权限拒绝而静默结束回合，现在给出清晰错误。这两处的共同问题是：把环境故障伪装成了业务结论。搜索没跑起来不等于没有匹配，写不进去不等于用户拒绝。

权限提示也在向可恢复方向调整。危险的 `rm` 提示现在会点名被标记的命令，并建议用 `${VAR:?}` 守卫，让 headless 运行有机会自行修正而不是直接失败。

## 工具语义的边界被收紧

Edit 工具修了两个容易造成数据损坏的问题。其一，转义反斜杠后跟 `uXXXX` 文本，此前被误判为 `\uXXXX` 转义，导致编辑非 ASCII 字符时反而改写了转义序列。其二，一个包含非 ASCII 文本的超大编辑未匹配时，此前报“正则表达式过大”，现在报“文件中未找到字符串”。前者是写错内容，后者是报错误导，两者都会让人对编辑结果失去信任。

路径处理也收紧了。工具调用的文件路径里若含以转义序列写出的 `\u0000`，此前会以“路径包含空字节”提前结束回合，现在转义的控制字符保持为字面文本。

沙箱规则同样从宽变严：`sandbox.excludedCommands` 的 glob 此前只要复合 Bash 命令中有一部分匹配，整条命令就被豁免；现在要求每一部分都匹配。这是安全边界的正确方向——豁免的单位应该是命令，不是命令的片段。

## prompt cache 的完整性被当成硬约束

这一版里有相当多的修复指向同一个后果：缓存未命中。

`/clear` 之后继续的会话（restart、`--continue`、`--resume`），如果 SessionStart hook 有输出，首条消息会缺失一部分，造成完整的 prompt cache 未命中。恢复的子 Agent 和 teammate 会重新渲染已加载的 MCP 工具定义，破坏该 Agent 的缓存。会话早期记录的附件在恢复或重启后被重新渲染，导致 extended thinking 丢失并错过缓存。

```flow
title: 缓存被击穿的两条路径
caption: 左侧是恢复流程引入的差异，右侧是渲染流程引入的差异，两者都会让前缀不再逐字节相同
layer: 触发 | *--resume 与 --continue* | 子 Agent 恢复 | 附件重渲染
layer: 差异来源 | SessionStart hook 输出 | MCP 工具定义重渲染 | 附件内容重新生成
layer: 后果 | 首条消息不完整 | 前缀变化 | extended thinking 丢失
layer: 结果 | *完整 prompt cache 未命中* | 该 Agent 缓存失效 | 缓存未命中
```

这些修复说明一个判断：prompt cache 不是优化项，而是被当作正确性约束在维护。任何会改变消息前缀的操作——hook 输出、工具定义重渲染、附件重建——都必须保证恢复后的字节序列与原始一致。

## 新增能力都指向边界控制

新增的 `AGENTS.md` 支持是一个兼容层：项目没有 `CLAUDE.md` 时改读 `AGENTS.md`，可在 `/config` 的 Project instructions 下修改，但 Bedrock、Vertex、Foundry 上尚不可用。

`CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1` 面向的是唯一出口是正向代理的 gateway：每个出站请求把主机名交给代理，而不是在本地解析。配套的还有 gateway upstream 上可选的 `headers` map，用于向你自己在 provider 前面跑的代理发送静态头。这两条合起来，是把“代理即边界”这个部署形态显式建模，而不是靠 DNS 行为隐式实现。

移除项同样值得注意：废弃的 TaskOutput 工具被删除，Claude 改用 Read 读取后台任务的输出文件，`taskOutputMaxChars` 设置和 `TASK_MAX_OUTPUT_LENGTH` 环境变量不再有任何效果。同时，非 SDK 或 IDE 启动的 `claude -p` 运行不再发起后台 Haiku 自动标题请求。减少隐式行为，是这一版反复出现的主题。

## 对自建系统意味着什么

如果正在把 Agent 嵌进自己的流水线，这一版给出的检查清单是具体的。

第一，确认失败路径有退出码而不是挂起，否则超时无法归因。第二，确认环境故障与业务结论在日志里可区分——搜索失败和没有匹配是两回事。第三，确认会话恢复后的消息前缀与原始逐字节一致，任何 hook 输出或工具定义重渲染都可能击穿缓存。第四，确认沙箱豁免的单位是完整命令而非片段。

这些都不是新功能带来的收益，而是把此前会静默出错的地方变成可观测的信号。一个 Harness 的成熟度，往往不体现在它能做什么，而体现在它出错时你能否知道错在哪。
